# 自动优化执行规程

本规程定义通用的优化工作流，不绑定特定项目、数据集、模型、日期、窗口、指标或Agent平台。当前工程的算法、数据和资源限制由工程有效约束及真人授权决定；执行后端负责把任务接入实际训练、构建、仿真或评测过程。

自动化提示词保存在本目录，可交给任意能读写本地文件、执行命令的Agent。无需专用模型API、会话ID或嵌套启动另一个Agent。状态落盘，跨Agent交接以真实产物和可核对授权为准。

## 开始与接续

在工程根目录使用统一CLI。以下命令不会依赖某个平台的私有工具：

```sh
python -m auto init
python -m auto status
python -m auto brief
python -m auto audit
python -m auto step --dry-run
python -m auto step
python -m auto run --steps 3
```

初始化冻结当前工程基线、执行后端和评测契约，不启动评测。一次step完成一个候选或接续未完成实验；run在总预算内连续执行。当前后端的参数和任务模式以CLI帮助为准，不能把当前工程的默认值当成所有任务都必须采用的规则。

需要指定任务时，在子命令前使用--campaign。检查已有进程，防止重入；已经完成的步骤和兼容产物尽量复用。stop停止继续启动实验，不擅自终止用户的其他进程。达到预算或停止条件后保留结果，不能通过另建任务绕过限制。

准备、运行与结算分别保存恢复点。中断后沿用同一实验标识，只重做尚未提交的准备或未完成步骤；准备中的输入改变时明确失败，不能拼接不同版本。恢复次数受--max-restarts限制，续跑继承已用评测时间，不重新获得完整超时预算。

audit独立核对任务与结果的绑定、源码和保存产物的一致性，不启动训练或评测。失败时给出非零退出码；历史记录缺少新版本证据时单列覆盖范围。保存产物损坏或改变时拒绝复用，不通过静默重算掩盖问题。结算重复执行不会重复追加同一实验结果，异常退出的工作进程不能凭成功报告被采纳。

负荷评测与正式推理共用部署出口，评分、重载和前缀隔离检查均包含已采用的后处理。当前配方的短长期输出存在交叉依赖，单链路任务也保存并复用两条独立训练的模型，只对所选链路计主指标。旧任务保留冻结评估器；需要采用新评测口径时新建任务，不混用历史排名。

完成报告在采纳前必须通过任务绑定、源码及必需产物完整性核验；继续评测前再次核对基线和父方案。基线无效时停止任务，修复原因后重新建立基线，不沿用失败比较。评测失败或结算无效时CLI返回非零退出码。

## 先冻结任务契约

开始比较之前，根据用户目标、工程约束和现有证据确定并持久化：

- 优化对象与允许修改范围，必要的运行依赖和信息可见性边界。
- 有效基线及其源码、配置、输入版本，拒绝把不兼容的历史最佳直接当本轮基线。
- 主指标、优化方向、汇总方式、对照方法和必要的正确性检查；分项退化与异常需要保留。
- 验证方法、样本或场景范围、有效评分位置及缺失处理。根据任务特点选择，不预设统一窗口数量或时长。
- 单次与总体预算、超时、可选目标以及停止条件，明确哪些动作已有真人授权。

评测契约冻结后，不看结果更换指标、基线、验证集合、评分位置或硬约束。候选实现与独立裁判分开；发现裁判缺陷时单独修复并重新建立可比基线，不混用不同口径的排名。

预测任务需要因果隔离时，应核对训练标签、特征时间、遮挡、未来扰动和模型重载；控制或优化任务有物理约束时，应独立重算轨迹、初末状态与约束。性能、构建、仿真等其他任务采用与其实际风险匹配的检查。不要把某一领域的检查强加到无关任务。

必要检查通过后，同口径主指标有正向改善即可更新实验最佳；不额外引入固定最低增益、所有分项都改善、多种子或统计显著性的统一门槛。缺陷修复与策略替换分别验收。检查通过、实验胜出、正式采用和外部系统接受分别表述。

## 假设驱动的搜索

先读brief提供的近期实验、主要退化、失败原因与剩余预算，再提出候选。每个候选说明：问题依据、准备改变什么、为何可能有效、如何证伪、预计改善和成本。公开资料只作为方法参考，不自动引入外部数据、模型权重或上传权限。

使用propose添加候选：--hypothesis写简要假设，--rationale写依据与预期，--ref记录资料来源，--overrides提供当前后端支持的参数覆盖，--source-dir提供已经完成的隔离代码候选。代码候选入队后不再修改；需要调整则提交新候选。

--expected-gain、--confidence和--cost-minutes用于排序，优先级为预计改善×信心/预计耗时。估计只决定搜索顺序，不能代替实测结果。初始基线始终先执行，未提供估计时保持稳定顺序，不捏造精确收益。

--parent可选择当前最佳、初始基线或本任务某个已完成实验，从而保留互补分支。子方案必须重新测量，组合两项独立改善不等于组合必然改善。是否更新全局最佳仍按固定主指标判断，不因选择了较弱父方案降低采用标准。

程序跳过可识别的源码或配置重复，记录原因，不占用实际评测次数。失败经验与分支来源长期保留；不要反复提交同一失败方案，不把修改假设文字当作新实验。尚未运行的错误或过时候选可用drop按提议标识撤回并说明原因，不手改历史记录。

## 每次自动化实际推进

1. 读取当前工程约束、任务状态与brief。没有任务时初始化；缺少必要信息时先做不依赖它的检查，仅在确实阻塞时请求补充。
2. 已有进程运行则只读观察；中断后接续已完成部分，避免重复启动和重复训练或构建。
3. 对就绪任务运行一个实际候选，读取评估结果、必要检查和分项变化，保留成功及失败证据。
4. 队列耗尽但预算尚存时，根据失败经验或主要误差提出并实施一个有依据的新候选；不能只列建议就结束。可从旧分支探索，但不覆盖历史产物。
5. 达到明确目标、预算、持续无改善或人工停止条件时停止。仅因困难或一次失败不能虚构任务已完成，也不能无限扩展预算。

## 授权、晋级与交接

高成本评测、全预算训练、正式部署、推送和上传分别依据当前真人授权执行。程序中填写授权文本只是审计记录，不能自授权限；明确授权已经覆盖的动作无需每轮重问。跨Agent交接需要能够核对授权范围，不能把旧聊天或状态自述当无限授权。

候选和运行产物保持实验隔离。只晋级被采用方案所必需的实现，不迁入搜索器、失败分支或临时编排。低预算改善只证明对应预算下有效，不能直接冒充最终部署收益；已有兼容产物不因出口修复重复计算。

报告实际动作、主指标变化、关键退化、失败原因、剩余预算和证据位置。没有实质变化时避免重复通知。完成结果与仍在运行、模拟与实测、本地验收与外部接受应分别说明。
