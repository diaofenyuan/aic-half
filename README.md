# AIC 半决赛：煤气发电量预测与发电优化

面向钢铁生产煤气系统，利用官方生产、耗气、气柜与电价数据，预测小机组组和全厂
发电负荷，并生成受机组容量、供气与库存约束的发电安排。项目从数据清洗、时序验证、
模型训练到测试推理、优化校验和结果打包，统一通过 `python main.py` 运行。

当前处于正式半决赛阶段，当前专注 `opt_result.csv`。默认 `python main.py` 只运行调度，
短期/长期预测训练与推理均暂停，组包原样复用已有预测表与模型。用户明确恢复后再启用。
项目采用已选定调度口径；完整导出、约束核验和线上成绩分别记录。

## 1. 快速开始

使用 Python 3.10，依赖见 `requirements.txt`。神经网络训练建议使用支持 CUDA 的
PyTorch；依赖准备完成后，训练与推理可离线运行，不调用在线模型或外部预训练权重。
赛事数据需由有权限的使用者自行放入 `data/`，仓库不提供原始数据与实验模型。

```powershell
python -m pip install -r requirements.txt
python main.py doctor                 # 只读检查数据阶段与文件
python main.py self-check             # 数据隔离、因果特征、模型及优化契约自检
python main.py opt --quick --experiment # 仅优化开发检查，预测表直接复用
```

获得完整训练授权后，按用途运行：

```powershell
python main.py                       # 默认 opt：复用预测表，只重新生成优化调度
python main.py infer                 # 与默认入口相同
python main.py run --experiment      # 完整历史开发实验
python main.py infer --experiment    # 完整测试推理实验，产物留在 tmp/tmp_outputs
python main.py infer --reuse-run outputs/<run_id> --experiment  # 完整冻结模型直接推理，不训练
python main.py verify --run-dir tmp/tmp_outputs/<run_id>
```

`infer` 与 `run` 的全量训练须由真人启动或明确授权。`--quick` 使用精简训练与
局部优化回放，专项校准的内层网络、树模型和缺测分支也沿用 quick 预算；完整与
quick 校准缓存不得混用，不能代表全量结果。开发验证、调参、消融与临时推理均写入
`tmp/tmp_outputs/`；`outputs/` 只用于用户明确要求归档的选定最终运行。

终端显示分阶段进度，重定向输出时自动关闭进度条；IDE 控制台可加 `--progress`，
只需日志时加 `--no-progress`。耗时取决于硬件、模型选择与优化规模，复用模型的
推理耗时不能等同于从头训练耗时。

## 2. 项目结构与整体流程

| 文件/目录 | 职责 |
|---|---|
| `main.py` | 唯一入口，组织训练、历史验证、测试推理和开发专项 |
| `config.py` | 数据阶段、字段角色、模型配方、物理约束与输出配置 |
| `data_cleaning/` | 数据识别、因果清洗、特征准备、质量与契约自检 |
| `main_s.py` / `main_l.py` | 独立短期、长期预测与评分 |
| `main_nn.py` | 神经网络训练、内部早停、推理与保存重载 |
| `main_opt.py` | 资源预测、历史物理标定、MILP 与连续代理回放 |
| `output.py` | CSV 校验、实际源码与模型归档、结果包生成 |
| `data/` | 只读官方数据，不进入 Git、源码快照或 ZIP |
| `tmp/tmp_outputs/` | 完整开发实验及其模型、数组、日志与结果 |
| `outputs/` | 明确归档的选定最终运行 |

正式推理流程为：读取合法训练阶段 → 因果清洗与特征构造 → 按冻结配方独立重训
短期、长期及资源模型 → 必要训练期标定 → 冻结最终模型 → 读取测试期合法观测 →
生成预测与每日优化安排 → 校验、归档和打包。正式推理不重新搜索候选或评估D折；
配方位于`FROZEN_LOAD_RECIPES`与`FROZEN_RESOURCE_RECIPE`。历史回测使用显式`run`，
资源侧也沿用冻结配方，不再用小时重规划结果选择每日发布方案。
测试输入不参与模型训练、选参或早停；前48小时耗气的操作校准候选尚未晋级。

## 3. 数据与信息边界

| 数据阶段 | 时间范围（2025年） | 当前用途 |
|---|---|---|
| `first_train` | 01-01～04-30 | 官方历史训练数据 |
| `first_test` | 05-01～05-02 | 已发布标签的官方历史训练数据 |
| `semi_train` | 05-03～09-30 | 官方历史训练数据 |
| `semi_test` | 10-01～10-10 | 旧推理输入；缺少 half_test 的其他环境兼容干跑 |
| `half_train` | 10-01～10-10 | 新发布训练标签，与旧阶段重叠时优先采用 |
| `half_test` | 10-11～10-31 | 冻结模型后的正式测试推理输入 |

每阶段识别 `load`、`gas`、`gas_user`、`gas_holder` 四表，支持文件名前缀及
`load_real.csv` 后缀。训练默认仅扫描 `role=train` 阶段，当前训练截止为
**2025-10-10 23:45**；训练入口会拒绝评测对象，即使截取其测试前前缀也不能混入。

滚动起报点 `t` 仅使用 **t 及此前已知的信息**，预测从 `t+15min` 开始。未来日历
与提前公布的全年电价可用；未来动态生产量、耗气与目标真值不可用。评测窗口的目标
整体遮挡，目标标签不插补；真实零负荷保留，缺失燃料不补零冒充零供气。

15 分钟基础网格按同一时间戳取值，不使用 t 之后分钟聚合、插值或 bfill。显式启用
的当前观测分支可附加 `(t-15min,t]`、`(t-60min,t]` 分钟统计、有效比例与缺测程度，
原始基础取值不变；当前燃料缺测时画像回退至未缩放版本。

连续用气列最多前向填补8步（2小时），长缺口保留缺失。`PreparedData.provenance`
独立记录合法观测与补值，随前缀截取、目标遮挡和耗气遮挡同步处理；这些标记不自动
进入已冻结模型的特征列。预测中的多设备合计表示可用组成项之和，须结合覆盖率；
物理核验账本通过 `observed_values` 只读原始合法观测，组成项不齐时不生成完整总量，
未观测用户仍保持未知。原始覆盖率与补值数量合并写入运行结果 JSON。同阶段冲突、
无效时间戳及扫描失败阻断数据契约检查；新发布阶段覆盖旧版本仍按阶段优先级处理。
`observation_quality` 提供逐时刻真实观测年龄，补值不重置年龄；首次观测前保持未知，
运行摘要区分首次观测前缺口和已有历史后的长缺口。物理账本中的未闭合差额包含
未观测用户、放散、库存交换和计量误差，仅作有符号诊断，不直接充当用户耗气或调度
资源。气柜数值范围检查与原始单位核验分别记录，不以量级一致代替独立单位依据。

派生特征的有效覆盖率按原始合法观测统计，前向填补不提高该比例。1e30量级采集哨兵、
负耗气与负库存记为缺测，不对正常极值做分位数裁剪，也不把越过安全线的真实柜位
裁回安全区。负荷标签独立检查容量；仅在两目标均有效且违反机组关系时同时遮挡，
包括`generator_all-generator_1`超过两台大机组240MW额定容量的情况。合法零值保留。

短期预测在起报点三气种发电耗气齐全时，可使用独立的3号高炉缺口恢复视图：已有
至少96个历史观测、其余4座高炉观测齐全时，以近28天最后4个合法观测的中位数
估计，距最后实测超过24小时即停止。估计只影响短期派生预测输入；原始流量、实测
覆盖率、长期模型和物理资源账本均保留原口径。耗气缺测时整条短期链路使用原输入。
恢复配方随模型保存，`--reuse-run` 严格保留归档中的实际配方、专项模型及校准参数，
不补训、不重新标定、不以当前配置覆盖旧配方。缺少必要分量或输入设置不兼容时明确
报错。该估计不代表缺失发生量真值已恢复。

本地 `half_test` 两个目标负荷列全为空，无法计算测试集的本地 1-MAPE；已发布发电
耗气仅提供测试期前48小时作为初始安排参考，后续为空属于官方设计，不补造真值。
测试推理覆盖完整 **2016 个起报点**；官方四表
已放置但覆盖不全时直接报错，不静默缩短窗口或退回旧数据。

## 4. 预测与资源模型

| 任务 | 输出/提前量 | 当前实现 |
|---|---|---|
| 短期负荷 | `generator_1`、`generator_all`；8步/2小时 | 独立 LightGBM、历史画像与神经网络候选，按开发验证选择融合 |
| 长期负荷 | 同上；96步/24小时 | 独立训练与选参，支持 Direct/Global/Grouped-H 树模型及神经网络融合 |
| 耗气缺测适配 | 按起报点观测状态启用 | 少特征专家、已知设备/分钟统计分支与冻结融合 |
| 小机组组专项 | 仅修正 `generator_1` | 短期两组三种子 TSMixer；长期三种子树专家与20 MW分歧门控 |
| 净资源模拟 | 三气种；96步 | 冻结28天时段画像分别预测发生量、已知生产需求与推测预留量，随后扣减 |
| 历史包络对照 | 三气种；96步 | 旧归档的 L1/L2 树模型、独立8步资源头与网络修正；无净资源模型的旧包继续明确标记为代理 |

`generator_1` 表示 4×50 MW 小机组组，总容量 200 MW；`generator_all` 为全厂
440 MW，两者之差对应 2×120 MW。短期与长期独立训练、选参和保存，不裁剪长期
结果冒充短期预测；默认也不将短期结果覆盖长期头部。

当前已归档主模型为因果 TCN 与 LightGBM/画像的融合，短期专项保留已晋级的
TSMixer。耗气缺测时读取冻结的少特征/观测分支，观测完整时使用选定主模型。

小机组组短期专项按训练前缀内的早停误差平方倒数聚合原三种子网络，以25%作为
另一组三种子网络的融合先验；后者保留训练期已观测耗气。当前按缺测前可见历史、
缺测时长和提前量学习阶段权重表，并以3/8收缩系数约束偏移，支持不足的单元保留
先验。该精修仅在当前发电耗气缺测时启用，通过单向投影保持总负荷与分组容量约束。
最终阶段参数使用合法训练前缀内两组完整20天折外路径拟合，监督时刻不晚于
2025-10-10 23:45；推理不在线使用测试标签更新权重。最终配方位于
`config.py` 的 `AVAILABILITY_FALLBACK`、`GENERATOR1_SPECIALIST`；实际使用的
模型、特征顺序、缩放和融合参数共同归档，重载不依赖开发缓存。

资源预测以历史机组耗气为代理标签，**不是完整气网净余气预测**。独立短头先通过
短提前量 WAPE 筛选，再在 A/B/C 完整21天控制回放中检查收益与降载；只有胜出的
模型和修正算子进入最终归档。资源预测不使用历史柜位特征。

## 6. 发电优化与结果边界

当前正式调度口径由用户选定，版本为 `20261027_daily_observed`。这些选择直接运行，
不再等待额外单位、路由或评分公式确认；选择来源和实际约束核验分别写入运行JSON。

- 每日07:00用同刻两柜观测复位，输出07:15至次日07:00的96步指令。复位差额单列，
  不充当物料流量；首尾窗口裁取完整提交网格。
- 柜1原始读数乘10000，柜2乘1。高炉1～3对应30万柜，4～5对应20万柜；生产与发电
  抽气按当期进气比例扣除，两柜不互相调气。
- 规划20%～85%、安全判定15%～90%，不使用跨日固定期末库存约束。超90%的推演
  富余按自动放散单独记账，不把放散当作实测量。
- 4×50MW和2×120MW机组，开机60%～100%，允许启停，不强制全开。聚合启停检查
  按分钟基准换算，总负荷判定66MW/15min，生成留60MW边距；持续开机单机检查1%/min。
- 先满足生产和库存边界，再优化收益。残差包含未观测用户、放散和计量差额，作为
  整体期望扣留，每次发布在此前28天按96个日内时段取中位数；不使用全期548917常数。
- 转炉7043.5不进入优化状态方程。转炉耗气以合法历史发电耗气包络作为可选资源；
  焦炉/转炉仅在富余时用于发电，不设固定配额或最低耗气，不虚构气柜。

原始数据按同时间戳瞬时值采样，时段气量采用该瞬时流量在15分钟内保持的积分近似。
所有计划只使用起报时刻已知信息；依赖下一柜位的残差在下一采样点到达后才可用。
测试前48小时之后的耗气不填造，缺少有效实测初态或实际无解会作为运行错误记录。

项目默认口径并不等于官方评分公式。内部推演、线上反馈与现场认证分别报告；
不因内部守恒而声称已经消除线上holder、composition或ramp违规。

## 7. 输出、提交核验与复现

明确归档的最终运行使用以下结构；开发实验将整个运行目录放到
`tmp/tmp_outputs/<experiment_id>/`，内容保持精简：

```text
outputs/<run_id>/
├── s_result.csv
├── l_result.csv
├── opt_result.csv
├── 咕咕嘎嘎-半决赛.zip
├── 源码/
├── 模型/
└── 报告/
    ├── 运行结果.json
    └── 运行日志.log
```

| 文件 | 内容 |
|---|---|
| `s_result.csv` | 起报点 datetime 与两个目标各8步预测，共17列 |
| `l_result.csv` | 起报点 datetime 与两个目标各96步预测，共193列 |
| `opt_result.csv` | 指令生效时刻 datetime、三气种优化耗气与两组优化发电量，共6列 |
| `模型/` | 本次实际使用的权重、预处理、融合、资源标定及必要元数据 |
| `源码/` | 运行开始时冻结的真实代码、清洗包与依赖说明 |
| `报告/运行结果.json` | 指标、模型来源、优化核验、耗时、限制与提交资格 |

时间统一输出为 `YYYY-MM-DD HH:MM:SS`。五个优化字段为
`opt_generator_use_blast_furnace_gas`、`opt_generator_use_coke_gas`、
`opt_generator_use_converter_gas`、`opt_generator_1`、`opt_generator_all`，
三气种字段为统一答复明确的必填项，两个负荷字段继续按赛题提供，三表放入同一ZIP。

覆盖校验逐点比较预期网格，拒绝缺行、多行、重复、乱序和时间错位。完整 half_test
的预测表为2016行，起报范围为2025-10-11 00:00至10-31 23:45；优化表按用户指定覆盖
2025-10-11 07:15至2025-11-01 07:00，共2016行、21个每日07:00发布窗口。
quick仅覆盖前两份计划，共192行、2个发布时刻。
每条优化指令的生成时刻早于生效时刻，运行摘要记录每日发布时刻及96步约束核验。

模型元数据与标定入口为 `模型/model_meta.json`，其他必要参数随实际模型分支保存。
新归档在模型元数据中保存重载所需选择参数、运行范围和源码指纹，重载不依赖
`报告/运行结果.json`。已有旧包可从其模型元数据恢复资源短头融合等必要设置。
ZIP只含有效结果CSV、源码与模型，不含原始数据、实验缓存、折外数组、日志或
`.gitignore`；仓库中的 `.gitignore` 正常保留。`报告/` 仅保留JSON和日志两个文件。
技术报告、答辩材料由用户编写，缺少手工资料不阻断机器结果生成。

仅优化运行记为 `FORMAL_OPT_COMPLETE`。`upload_ready` 表示三表及ZIP完整，
`submittable` 表示完整正式范围且通过所选口径下的模型约束核验；现场安全认证另列。
求解无解时仍生成因果兜底表并标记 `FORMAL_OPT_FALLBACK`、`submittable=false`，
保存具体失败原因，不能把兜底当作可行最优解。`verify` 分别报告归档完整性与约束结果。

复用已有合法最终模型时可运行：

训练默认缓存相同输入、配方、随机种子及运行环境下的树模型、负荷神经网络与最终校准表，
缓存保存在 `tmp/tmp_outputs/training_cache_v1/模型/`，不混入提交包。训练数据、截止点、
特征、源码、配置或依赖版本变化会使缓存失效；完整性校验失败时重新拟合。中断后重跑
可复用已完成组件，运行 JSON 的 `training_cache` 记录命中和未命中次数。冷训练与缓存
复用耗时须分别报告；如需强制从头训练，可在 PowerShell 设置 `$env:AIC_TRAINING_CACHE='0'`，
结束后用 `Remove-Item Env:AIC_TRAINING_CACHE` 恢复默认行为。此设置不改变全量训练授权规则。

```powershell
python main.py opt --reuse-run outputs/<已有预测归档>
python main.py verify --run-dir tmp/tmp_outputs/<新运行>
```

`--reuse-run` 也可指向本项目结果包的本地解压目录，不要求解压到原项目路径；
模型路径兼容 Windows 与 Linux。ZIP 中的原始数据仍由赛事环境提供，不随包分发。

复用模型的训练截止须早于测试起报点；正式训练只使用已保存的晋级配方。
归档模型需通过保存重载一致性检查，改变数据、代码或配置后以新运行记录为准。
源码快照在训练前生成，保存模型及打包时只核验、不覆盖。运行中修改正式源码或
冻结快照会拒绝归档并记录失败，防止新代码与旧训练结果混装；历史运行快照不更新。

## 8. 实验代码隔离

正式入口只保留推理、历史回测及必要检查。历史研究实现、失败候选和旧专项命令已迁入

不能阻断新规则落地；未完成的物理核验只限制相应结论与提交状态。
官方允许的未观测用户历史推测可以建模验证，保留inferred标记，无需等待全部用户实测量。
