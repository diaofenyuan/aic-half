# AIC 半决赛：煤气发电量预测与发电优化

基于赛事官方生产、煤气用户、气柜与电价数据，预测煤气发电负荷，并生成满足生产、
机组和库存约束的每日发电计划。预测对象为小机组组 `generator_1` 与全厂
`generator_all`，分别输出未来 2 小时和 24 小时的负荷。

核心代码已替换为新版实现：独立短期/长期 **LightGBM 与冻结历史画像**、因果资源建模、
双柜每日固定 **MILP** 调度。保留现有模块布局，不使用神经网络。模型、数据质量、
逐日计划和完整运行分别验收；代码完成替换不代表任意输入下的调度约束均已通过。

## 1. 开发基线

- 全部核心实现已重新编写，不依赖旧模型工厂、网络或专项专家。
- 旧实验、模型、融合参数、专家门控、经验调度参数、训练缓存及晋级结论不再继承。
  历史文件仅供问题追溯，不自动删除，也不作为新版有效基线。
- 重新建立因果朴素基线与最小 LightGBM 基线，再按实际部署输出比较候选。
- 数据与时间契约、独立约束核验优先于调参；先验证计划可行性，再比较收益。
- 新版采用独立模型与缓存版本。旧模型包不因目录或字段相同而自动兼容。

常驻规则、官方答疑、训练授权及已选物理口径以 [AGENTS.md](AGENTS.md) 为准。
研究候选与实现过程不写入常驻文档，证据统一记录在对应运行 JSON 和日志中。

## 3. 数据与信息边界

### 数据阶段

| 目录 | 时间范围（2025 年） | 角色 |
|---|---|---|
| `first_train` | 01-01～04-30 | 官方历史训练数据 |
| `first_test` | 05-01～05-02 | 已发布标签的官方历史训练数据 |
| `semi_train` | 05-03～09-30 | 官方历史训练数据 |
| `semi_test` | 10-01～10-10 | 历史阶段输入，不替代正式 half_test |
| `half_train` | 10-01～10-10 | 新发布训练数据，重叠时优先采用合法新版本 |
| `half_test` | 10-11～10-31 | 正式测试输入，不进入训练、选参或全局标定 |

每阶段包含负荷、发生量、用户耗气和气柜四类表。正式训练标签截止为
**2025-10-10 23:45**；各历史验证折使用各自更早的截止点。

### 因果与质量要求

- 起报点 `t` 只使用 `t` 及此前已知信息，预测目标从 `t+15min` 开始。未来日历与
  官方提前公布的全年电价可用，未来动态生产量、耗气和目标真值不可用。
- 数据为瞬时值。15 分钟网格取同时间戳观测，不使用未来分钟聚合、双向插值或
  `bfill`；流量积分必须声明区间与保持假设。
- 评测窗口目标整体遮挡，评分真值与模型输入分离；标签不插补，合法零负荷保留。
- 过程缺失保留 NaN、原始有效比例及观测年龄；缺失燃料不补零冒充零供气。
  `1e30` 等无效记录不能作为实测柜位，真实越界柜位不得裁回安全区。
- 流量标准单位为 m³/h，库存为 m³。历史原始柜1×10000、柜2×1；已统一为 m³
  的输入直接使用。按数据版本声明转换来源，只转换一次。
- 测试负荷标签为空，不计算本地测试 `1-MAPE`。测试耗气仅前 48 小时有观测，
  只能随时间到达用于允许的调度初态和耗气校准；后续缺失不填造。
- 新版负荷首版不使用发电耗气及其同源派生量，调度视图单独读取合法耗气前缀。
  历史验证在选定窗口整段遮挡目标，并模拟前 48 小时后的耗气缺失；长期标签不可见的
  风险按需要选择代表性连续窗口检查，不要求每次训练都做21天历史回测。

仅使用赛事官方数据与通用开源依赖，支持离线复现；禁止外部数据、预训练权重、
闭源在线模型、未来信息泄露、测试反推标签以及人工修改预测或优化结果。

## 4. 建模与调度契约

### 负荷与资源

| 任务 | 约定 |
|---|---|
| 短期负荷 | 两目标、8 步、2 小时，独立训练与保存 |
| 长期负荷 | 两目标、96 步、24 小时，独立训练与保存 |
| 学习模型 | 短期独立共享8步；长期按1–8、9–32、33–96步分别训练LightGBM，仅保存实际采用分量 |
| 负荷配方 | 短期等权组合逐步预测与完整8步窗口的相对损失中位水平，两者均独立预测全厂与大机组组再求差，保留28天半衰期与0.6权重因果一致化。长期等权组合全厂与小机组占比模型、56天逐起报点密集训练的双目标因子模型；使用相对误差权重及过程、机理、缺失状态特征。组合固定，不按测试时段选模型 |
| 冻结画像 | 仅训练截止前28天同日内时段中位数，随模型保存；推理不读取测试标签更新 |
| 形状与缺测 | 因子训练按三天块使用块前28天形状，并换算相对L1权重；最近过程值另设特征，一天后停用，原始NaN保留 |
| 窗口水平与占比 | 短期窗口分量只使用标签完整的未来8步训练，以冻结形状换算每步相对损失权重；长期占比标签为小机组组/全厂，按训练标签全厂MW换算损失权重，推理使用预测全厂与预测占比还原负荷 |
| 相对过程量 | 长期增加过程量相对过去1天/7天中位数的比例与偏差、同炉发生量和热风炉耗气的成对收支；分母无效时保持NaN，不把部分收支解释为完整可用煤气 |
| 机理外生量 | 长期区分同炉热风炉需求和其他已观测用户需求，构造分组收支代理、覆盖率及严格向后滚动过程水平；未知需求保留缺失，不引入未核验热值常数或未来实测过程量 |
| 预测关系 | 小机组组 0～200 MW，全厂不超过 440 MW，两者差不超过 240 MW |
| 高炉资源 | 发生量、已知生产需求与整体残差分别建模或估计，不把发生量直接当净余气 |
| 未观测残差 | 发布前 28 天、96 个日内时段中位数；依赖下一柜位的记录闭合后才可用 |
| 焦炉/转炉 | 无独立气柜，允许合法历史耗气代理资源，无固定配比或最低耗气 |
| 气电映射 | 合法历史前缀内标定、留出验证，保持 inferred；不套用未经量纲核验的热值 |

短期不得由长期结果裁剪冒充。资源预测不使用历史柜位特征；历史耗气包络不等于
真实净余气，推断残差不等于真实用户耗气。具体模型配方必须以新版验证证据确定。
转炉耗气包络在每日发布时，仅当截至同刻的连续4个15分钟实测均有效时，以中位水平
校准近期预测，差额按16步半衰期衰减。缺测时原样保留模型预测，不沿用陈旧耗气或补零；
校准仅用于调度耗气特性，不重训模型，也不将历史耗气包络表述为真实净余气。

### 每日调度

- 每日 **07:00** 固定发布一次，生成 **07:15 至次日 07:00** 的 96 条指令；
  `datetime` 为指令生效时刻，当天计划不随日内观测重新发布。
- 机组为 **4×50 MW + 2×120 MW**，开机负荷为额定的 **60%～100%**，允许启停。
- 按已选分钟基准换算聚合爬坡：小机组组 30 MW/15min，总负荷核验
  66 MW/15min、生成留 60 MW 边距；持续开机单机检查 1%/min，启停按聚合检查。
  小机组组使用准确的30 MW上限，避免阻断最低30 MW开机状态；柜位恢复分支使用
  已采纳的30/66 MW硬上限，正常计划仍保留60 MW总负荷生成裕度。
- 两个高炉气柜独立，容量 **30 万/20 万 m³**；规划 **20%～85%**，安全核验
  **15%～90%**。高炉1～3和4～5分别对应两组管网，不跨柜调气。
- 已知用户及发电耗气按当期进气比例分摊；用户管网收支与气柜直接出气分开建模，
  不重复扣气。焦炉/转炉不虚构库存，转炉7043.5不进入优化状态方程。
- 每日 07:00 使用同刻有效实测双柜重锚，复位差额与物料流量分开记账。
  桥接优先使用同刻已知的发生量与生产需求；仅缺测发生量在关联过程支持下使用首15分钟
  过程预测作持平近似，单独记录推测来源与训练截止，保留原始NaN和已知零值。
  明确首条指令前的桥接、逐柜初末态和跨日衔接，不默认历史边界为全停或稳态。
  核验单列实测锚点、首条指令前桥接、指令执行后柜位的越界与未知项；完整安全门槛
  仍包含全部初末态，不以起始越界归因或缩短验证窗口改写 `submittable`。
  两柜容量来源为数据字典“数据说明”A21，15%安全比例来源为赛题约束，4.5万m³是推算值。
  本地严格锚点检查不等于官方直接否决越界锚点；现有答复也未给予锚点自动豁免。
  运行记录分别列出初态、执行后轨迹、规划裕度及提交条件，官方判定保持未知。
- 不设置跨日硬期末库存；超90%的计算富余按已选本地自动放散模型记账，不能修复
  低柜位欠气，也不代表官方逐柜放散能力。
- 先保证生产、机组、库存与守恒约束，再优化分时收益。计划、事后代理执行、真实
  收益与现场安全认证分别解释，不声称复刻官方评分模型。
- 联合求解三气种耗气、六台出力与逐柜库存，以经验分组映射软目标、历史耗气支持域诊断、映射敏感性、
  末端衔接及库存风险作为已归档的控制依据。默认在联合收益参考计划的99%毛收益底线内
  优化电价加权负荷比（`benefit_fraction=0.99`），保持原有硬约束及每日固定发布契约，
  分别记录收益、电价加权比、降载及放散；原始比值不冒充线上 `price_eff`，经验关系不解释为官方固定配比。
- 分组再分配采用训练截止前28天耗气与小机组组负荷的非负映射，留出7天检查误差。
  标定可信时固定三气种耗气、总负荷和末条逐台状态，仅改善组间分配与小机组组平滑；
  标定不可信或当日再分配无解时保留原计划，不撤销此前已发布指令。
- 模型格式为 `lgbm_core_v3`，负荷契约为 `load_coupled_ensemble_v5`，保存固定组合的各分量、权重与独立配方，并核对覆盖和训练截止；包含分组映射与验证参数。旧格式不自动迁移；采用方案
  的经验映射不等于官方 composition 规则，不承诺消除线上触发。
  历史配比不限制实际气种组合；各气种按可用气量约束，分组爬坡按实际决策功率核验。
  联合控制参数使用独立的 `joint_optional_prefix_v4` 契约，缺失或配方不同的归档明确拒绝复用，
  预测树兼容不等于控制参数齐全；控制标定和保存重载不要求重训未修改的预测模型。
- 高炉发生量缺失且关联热风炉有观测时，可用独立归档的共享 LightGBM 过程模型估计
  高炉1～3组未来发生量；缺失输入保持缺失，热风炉零值不代表高炉停产或零供气。
  模型使用训练前缀、炉别归一化、输入遮挡和0.25分位损失，以稳定性为优先控制缺测资源
  的高估风险；分位数不代表已获得概率覆盖保证。不插补标签、不使用柜位特征；缺乏训练
  支持或关联过程缺测时保留原有资源预测并记录原因。过程模型独立记录实际训练截止，
  可早于其余资源模型，禁止越过资源归档截止或发布时刻，旧过程模型不能静默迁移。

上述为已选项目口径，不再等待额外确认才能实施；官方事实与项目假设的区别见 AGENTS。

## 5. 运行入口

开发环境为 **Python 3.10、CPU 离线运行**，依赖版本见 `requirements.txt`，无 PyTorch。
默认使用本机 **16线程**作为 LightGBM、HiGHS 和数值库的线程预算；模型顺序训练，
避免模型并行与内部线程同时开满。可用 `--threads` 降低预算。

```powershell
python -m pip install -r requirements.txt
python main.py doctor
python main.py self-check --threads 16
python main.py infer --quick --experiment --threads 16
```

正式训练得到当前任务授权后运行；默认入口直接按已选配方训练，不先执行历史回测或重新选参：

```powershell
python main.py --threads 16
```

兼容模型或预测可显式复用，检查归档使用 `verify`：

```powershell
python main.py infer --reuse-run outputs/<run_id> --experiment --threads 16
python main.py opt --reuse-run outputs/<run_id> --experiment --threads 16
python main.py verify --run-dir outputs/<run_id>
```

需要历史评估时单独执行；完整回测也需要当前任务训练授权，不是正式训练的前置命令：

```powershell
python main.py run --threads 16
```

训练与复用职责如下：

| 入口 | 职责 |
|---|---|
| `python main.py` / `infer` | 独立训练已选配方，生成预测、每日计划和归档，不自动执行ABC或重新选参 |
| `run` | 按需显式执行的隔离历史回测，结果进入实验目录，不是训练前置步骤 |
| `infer --reuse-run <run_dir>` | 复用同版本兼容模型，重新推理，不补训或重新标定 |
| `opt --reuse-run <run_dir>` | 复用兼容预测和资源参数，仅重新生成调度 |
| `doctor` | 检查数据阶段与运行条件 |
| `self-check` | 检查因果性、数据、模型及优化契约 |
| `verify --run-dir <run_dir>` | 检查结果覆盖、归档与约束证据 |

可通过 `python main.py --help` 查看当前参数，`--run-id` 指定新的运行标识。`--quick` 用于精简开发验证，与其他
实验均须写入 `tmp/tmp_outputs/<experiment_id>/`，不能视为正式完整验收。

**Agent 不得自行启动全量训练。** 完整 `run` / `infer` 须由真人在当前任务明确发起
或授权；历史授权不自动延续。quick与历史开发模型不能冒充正式最终模型。

## 6. 验证与验收

开发评估与正式训练分开。模型或策略在同一基线、信息边界、窗口和评分口径下，
实际部署主指标有正向改善即可采用；不设置固定最小增益或逐折、单目标退化否决线，
也不强制完整ABC、多种子或统计显著性。比较前固定主指标，分项退化与波动如实记录。
官方要求与缺陷修复按正确性验收，不要求提分。

开发先用事先固定的近期代表窗口；重大模型、资源或跨日策略变更按风险补充代表窗口，
出现异常或结论冲突时再扩展。配方确定后，正式训练按合法截止使用已选历史范围，
不重复选模验证；复用与出口修复不重训未修改的模型。

|---|---|---|

| B | 07-05～07-25 | 07-04 23:45 |

D 折（09-05～09-25）已多次查看，仅作历史诊断，不用于选参或称为独立盲测。
现有显式 `run` 使用 A/B/C，`run --quick` 使用 A/B；其他专项可在隔离实验中声明窗口，
不要求调用完整 `run`。训练样本按最大目标时刻隔离，早停与标定使用合法训练前缀。

负荷主指标为 `100×(1-MAPE)`；零标签不进分母，单列绝对误差。检查两目标、各提前量、
偏差与最差窗口，按预先固定的整体主指标判断提升，不要求所有分项都获胜。
纯预测回测不以气柜安全或调度收益判断预测方案是否采用；完整运行中的调度结果另行核验。

资源检查分气种 WAPE、偏差和累计量误差，真实零气量上的误报计入分子。最终资源与
调度候选按风险在选定窗口回放，检查覆盖、生产供气、逐柜守恒/安全、机组、爬坡、
跨日边界、降载与收益。完整正式运行逐日检查全窗口硬约束；测试无观测区间不伪造完整执行收益。

必须通过未来扰动不影响既有输出、保存重载一致性和导出后独立核验。随机候选可用
单种子，有异常或结论冲突时再按需要复核；小幅提升如实说明不确定性。测试聚焦
高风险关键链路，不重复验证已淘汰候选。采用标准放宽不改变数据合规、功能正确和调度硬约束。

历史回测逐折保存模型与三表，指标汇总到单一JSON/日志；不会将开发折组装为正式
提交包。双柜锚点缺失、资源仅为耗气代理或实际无解时，仍完整导出并保留失败原因。

模型保存实际部署所需的特征、权重、预处理、后处理、标定及版本；源码在运行开始时
冻结，后续仅核验，不将新代码与旧模型混装。现阶段提交 ZIP 根目录仅含 `s_result.csv`、
`l_result.csv`、`opt_result.csv`，避免评分服务下载提交结果时卡死；源码、模型和报告
仅在本地运行目录归档。打包和 `verify` 严格检查三表白名单及内容一致性，拒绝额外或重复
条目。实验按专用路径归档，不进入正式 outputs。

`upload_ready` 只表示三表和 ZIP 完整；`submittable` 还要求完整正式范围及已选项目
口径下的硬约束通过。无解仍生成因果兜底和完整机器包，明确标记约束失败与
`submittable=false`，不能以顶层成功状态掩盖失败。现场认证、官方接受与线上分数另列。
报告区分实测初态、输出/时间约束和本地推测模型检查。初态及20%～85%规划裕度的
严格核验属于项目口径，不据其失败断言官方判违规；官方柜位重建与锚点边界处理标为未知。
低柜位恢复依次最小化执行后越界步数、安全库存缺口，再优化原有裕度与收益目标；
记录各阶段的最优性证据，恢复分支仍如实保留本地约束失败。
约束失败的推理/调度运行以退出码2结束，执行错误为1，正常实验或完成为0。
`verify` 的归档完整性与约束结果分开输出；不能将归档通过理解为计划可行。
首步资源与爬坡冲突时，导出分支保持机组/爬坡约束并最小化显式资源超额，不将整天
负荷固定为首步值。该超额逐日记录，仍属于约束失败，不能将其当作正常可用煤气。

运行证据仅合并到 JSON/日志，不自动生成技术报告、清洗报告、PDF、Word、PPT 或额外
图档；手工材料由用户编写，缺少手工材料不阻断机器结果包生成。
