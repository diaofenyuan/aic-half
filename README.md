# AIC 半决赛：煤气发电量预测与发电优化

面向钢铁生产煤气系统，利用官方生产、耗气、气柜与电价数据，预测小机组组和全厂
发电负荷，并生成受机组容量、供气与库存约束的发电安排。项目从数据清洗、时序验证、
模型训练到测试推理、优化校验和结果打包，统一通过 `python main.py` 运行。

当前处于正式半决赛阶段。完整测试推理链路已经跑通；预测历史验证、代理优化模拟与
正式提交资格分别记录。测试负荷标签为空，优化物理口径尚未完成正式核验，当前实验
产物仍为 `submittable=false`。

## 1. 快速开始

使用 Python 3.10，依赖见 `requirements.txt`。神经网络训练建议使用支持 CUDA 的
PyTorch；依赖准备完成后，训练与推理可离线运行，不调用在线模型或外部预训练权重。
赛事数据需由有权限的使用者自行放入 `data/`，仓库不提供原始数据与实验模型。

```powershell
python -m pip install -r requirements.txt
python main.py doctor                 # 只读检查数据阶段与文件
python main.py self-check             # 数据隔离、因果特征、模型及优化契约自检
python main.py run --quick            # A/B 历史开发验证，产物写入 tmp/tmp_outputs
```

获得完整训练授权后，按用途运行：

```powershell
python main.py                       # 默认 infer：训练后执行完整半决赛测试推理
python main.py infer                 # 与默认入口相同
python main.py run --experiment      # 完整历史开发实验
python main.py infer --experiment    # 完整测试推理实验，产物留在 tmp/tmp_outputs
python main.py verify --run-dir tmp/tmp_outputs/<run_id>
```

`infer` 与 `run` 的全量训练须由真人启动或明确授权。`--quick` 使用精简训练与
局部优化回放，专项校准的内层网络、树模型和缺测分支也沿用 quick 预算；完整与
quick 校准缓存不得混用，不能代表全量结果。开发验证、调参、消融与临时推理均写入
`tmp/tmp_outputs/`；`outputs/` 只用于用户明确要求归档的选定最终运行。

终端显示分阶段进度，重定向输出时自动关闭进度条；IDE 控制台可加 `--progress`，
只需日志时加 `--no-progress`。耗时取决于硬件、模型选择与优化规模，复用模型的
推理耗时不能等同于从头训练耗时。

## 2. 项目结构与整体流程

| 文件/目录 | 职责 |
|---|---|
| `main.py` | 唯一入口，组织训练、历史验证、测试推理和开发专项 |
| `config.py` | 数据阶段、字段角色、模型配方、物理约束与输出配置 |
| `data_cleaning/` | 数据识别、因果清洗、特征准备、质量与契约自检 |
| `main_s.py` / `main_l.py` | 独立短期、长期预测与评分 |
| `main_nn.py` | 神经网络训练、内部早停、推理与保存重载 |
| `main_opt.py` | 资源预测、历史物理标定、MILP 与连续代理回放 |
| `output.py` | CSV 校验、实际源码与模型归档、结果包生成 |
| `data/` | 只读官方数据，不进入 Git、源码快照或 ZIP |
| `tmp/tmp_outputs/` | 完整开发实验及其模型、数组、日志与结果 |
| `outputs/` | 明确归档的选定最终运行 |

正式推理流程为：读取合法训练阶段 → 因果清洗与特征构造 → 按冻结配方独立重训
短期、长期及资源模型 → 必要训练期标定 → 冻结最终模型 → 读取测试期合法观测 →
生成预测与每日优化安排 → 校验、归档和打包。正式推理不重新搜索候选或评估D折；
配方位于`FROZEN_LOAD_RECIPES`与`FROZEN_RESOURCE_RECIPE`。历史回测使用显式`run`，
资源侧也沿用冻结配方，不再用小时重规划结果选择每日发布方案。
测试输入不参与模型训练、选参或早停；前48小时耗气的操作校准候选尚未晋级。

已放置但覆盖不全时直接报错，不静默缩短窗口或退回旧数据。

## 4. 预测与资源模型

| 任务 | 输出/提前量 | 当前实现 |
|---|---|---|
| 短期负荷 | `generator_1`、`generator_all`；8步/2小时 | 独立 LightGBM、历史画像与神经网络候选，按开发验证选择融合 |
| 长期负荷 | 同上；96步/24小时 | 独立训练与选参，支持 Direct/Global/Grouped-H 树模型及神经网络融合 |
| 耗气缺测适配 | 按起报点观测状态启用 | 少特征专家、已知设备/分钟统计分支与冻结融合 |
| 小机组组专项 | 仅修正 `generator_1` | 短期两组三种子 TSMixer；长期三种子树专家与20 MW分歧门控 |
| 可发电煤气资源 | 高炉、焦炉、转炉三气种；96步 | 逐气种选择 L1/L2 树模型，独立8步资源头及经验证的网络修正 |

`generator_1` 表示 4×50 MW 小机组组，总容量 200 MW；`generator_all` 为全厂
440 MW，两者之差对应 2×120 MW。短期与长期独立训练、选参和保存，不裁剪长期
结果冒充短期预测；默认也不将短期结果覆盖长期头部。

当前已归档主模型为因果 TCN 与 LightGBM/画像的融合，短期专项保留已晋级的
TSMixer。耗气缺测时读取冻结的少特征/观测分支，观测完整时使用选定主模型。

小机组组短期专项按训练前缀内的早停误差平方倒数聚合原三种子网络，以25%作为
另一组三种子网络的融合先验；后者保留训练期已观测耗气。当前按缺测前可见历史、
缺测时长和提前量学习阶段权重表，并以3/8收缩系数约束偏移，支持不足的单元保留
先验。该精修仅在当前发电耗气缺测时启用，通过单向投影保持总负荷与分组容量约束。
最终阶段参数使用合法训练前缀内两组完整20天折外路径拟合，监督时刻不晚于
2025-10-10 23:45；推理不在线使用测试标签更新权重。最终配方位于
`config.py` 的 `AVAILABILITY_FALLBACK`、`GENERATOR1_SPECIALIST`；实际使用的
模型、特征顺序、缩放和融合参数共同归档，重载不依赖开发缓存。

资源预测以历史机组耗气为代理标签，**不是完整气网净余气预测**。独立短头先通过
短提前量 WAPE 筛选，再在 A/B/C 完整21天控制回放中检查收益与降载；只有胜出的
模型和修正算子进入最终归档。资源预测不使用历史柜位特征。

## 6. 发电优化与结果边界

优化使用 MILP 在可发电煤气包络与气柜缓冲内重排时段，结合江苏分时电价安排发电，
不直接复制历史耗气。主要约束包括：

- 4×50 MW 与2×120 MW机组，开机功率为额定的60%～100%。
- 爬坡按赛事修正的1%及原赛题分钟基准换算到15分钟，按小机组聚合负荷和总负荷检查启停。
- 气柜保持15%～90%安全区，计划额外保留5%裕度，并约束期末库存。
- 焦炉、转炉没有独立柜位，不虚构库存；无效的1号高炉气柜不参与状态。

安全区按独立气柜分别计算：1号柜4.5万～27万m³，2号柜3万～18万m³，不合并库存。
一号柜未部署意味着其安全尚未核验，不能把二号柜计划可行性扩展成两柜安全结论。

默认采用确定性 `point` 供气模式。最新官方答复要求每日固定发布，日内不得刷新：
默认固定每日07:00，规划07:15～次日07:00的96步；可在`config.py`的
`OPT_CONFIG.publication_time`调整为其他固定的15分钟网格时刻。首尾窗口按长期表的
时间范围截取，完整测试期2016行对应22个发布时刻，未提交的窗口外时段不计收益。
覆盖首日凌晨的计划在前一天07:00发布，资源模型、资源网络和气电标定须在该时刻前
冻结；负荷预测仍可使用其首个起报点之前的合法训练标签。复用模型若超过实际发布
截止将明确拒绝，不能将后来训练的权重用于早已发布的指令。
两个气柜独立，不合并容量；当前只部署二号柜。计划库存跨日
接续，不用历史柜位重置优化库存，也不把日内事后降载覆盖到已发布CSV。

当前每日控制保留14万m³期末库存与200MW末步负荷上限，避免下一份计划从不可达状态
开始。规划负荷基准上限240MW，发布时间三气种耗气齐备时按已知耗气的经验能量调整，
最高280MW；缺测保持缺测并使用基准上限。这些是A/B/C验证后的控制参数，不是官方
强制运行限值。事后代理执行允许按当时已观察资源补偿气种配比，仍满足聚合爬坡、
最低开机负荷和柜位约束，不改写已发布CSV。

计划收入、代理执行收入、历史发电收入和真实气网净效益分别记录；代理释放量也不
等于现场放散。真实净余气、历史放散和官方罚金缺失时，不计算官方净效益提升率。

此前完整测试实验曾输出2016步计划，仅191步具有已发布耗气可用于事后回放；其旧爬坡
和末端覆盖不符合2026-10-26统一答复后的实现，不能沿用旧校验作为新规则验收。
当前优化时间列与长期表相同，不另加测试日期之外的尾段。测试期耗气仅前48小时提供，无法完整事后回放
属于数据设计边界；不据此补造执行收益，也不把计划可行性当作真实气网安全证明。

气电换算采用合法训练前缀内的非负无截距回归，末7天留出检查R²、WAPE与偏差。
这只核验耗气输入到总负荷MW的综合经验映射，不分别识别热值、效率。
总耗气不唯一决定小机组负荷，机组组之间的供气分配属于控制决策。当前根据已优化的
两组功率显式分配三气种耗气，逐步检查分组耗气合计和两组能量守恒；该实现仍采用
共享经验效率，不能据此声称两组独立效率或官方修正阈值已经核验。
2026-10-26答复已明确
发生量和消耗量标准单位为m³/h；既有回归参数仍保留 `inferred`。
官方参考热值按原文记录为高炉750、转炉1250、焦炉4150 J/kg；质量比热值与体积流量
不能直接换算为MW，缺少密度和效率时不直接替换经验系数，也不擅自修改通知单位。
本次固定方法在A/B/C各21天及已发布半决赛训练期10天的转换诊断WAPE为2.72%、
3.72%、3.34%、4.64%；这是已复用训练期的同时间戳气电换算诊断，不是预测或测试成绩。

生产用户核算按发生量扣除已知热风炉、生产用户和混气站进气。混气站在上游扣一次，
不再追加下游混气用户造成重复扣减；关键项缺测则保留缺测，不能补零制造净余气。
转炉第三用户列全缺、部分历史高炉关键项缺测、转炉倍率无法闭合全部用量，因此账本
只表示已知扣减后的剩余量，尚不能替换正式资源预测或证明优先生产用户全时段供气。

统一答复已明确1号柜30万m³、2号柜20万m³，以及优化datetime为指令生效时刻。
当前部署2号柜，训练期数值范围通过对应容量核验；1号柜仍未部署，不猜测其缩放。
1号柜原始读数约0～27；多种倍率都能符合容量范围而给出不同安全判断，因此不能将
未经单位换算的原值直接判作低柜位。优化不调用其未知库存；绝对安全状态保留未核验。
转炉原始量级归一仍未闭合，7043.5保持历史推算标记；标准m³/h已经明确，不再索要。
发电耗气列的m³/h与经验气电系数独立于原始发生量倍率；原始发生量只作传感器特征及
推算账本，不直接作为已核验的物理流量约束。
最新答复允许从合法历史数据推测未提供的生产用户耗气，推测量保留 inferred 标记。
净资源候选仍须通过完整预测与调度验收；官方放散系数、真实历史放散及原始单位
闭合证据不足时，不能据此宣称真实气网已通过核验，继续保留模拟状态。

最新答复明确，`Model` 会在煤气量与提交负荷偏差较大时修正负荷，或在负荷未提交时
推断负荷，再据此计算效益。因此大量触发不能视作普通计算提示；本地经验转换误差
也不能冒充官方未公开的修正阈值。

提交核验区分官方已知规则、训练标定通过、单位或数据缺口、尚未完成的调度验收，
分别记录在 `physical_validation`，不再把所有未通过项笼统归为“缺官方依据”。记录
随实际资源模型保存，旧模型可只读复核合法训练前缀补齐，系数不一致时不借用新参数
的验证结论。单个 `submittable` 或物理可行布尔标记不能放行；代理模型继续阻断正式提交。

2026-10-26本轮未执行全量训练或正式测试预测。前48小时校准、严格净资源账本及
两座气柜的联合调度候选保存在`tmp_main/20261026_dispatch_completion/`，不随正式
源码交付。A/B轻量模型验证与既有权重的A/B/C完整每日回放结果位于对应实验JSON。
上述旧验收发现的每日计划及执行失败，已在`20261026_operational_repair`中定位并修复。

## 7. 输出、提交核验与复现

明确归档的最终运行使用以下结构；开发实验将整个运行目录放到
`tmp/tmp_outputs/<experiment_id>/`，内容保持精简：

```text
outputs/<run_id>/
├── s_result.csv
├── l_result.csv
├── opt_result.csv
├── 咕咕嘎嘎-半决赛.zip
├── 源码/
├── 模型/
└── 报告/
    ├── 运行结果.json
    └── 运行日志.log
```

| 文件 | 内容 |
|---|---|
| `s_result.csv` | 起报点 datetime 与两个目标各8步预测，共17列 |
| `l_result.csv` | 起报点 datetime 与两个目标各96步预测，共193列 |
| `opt_result.csv` | 指令生效时刻 datetime、三气种优化耗气与两组优化发电量，共6列 |
| `模型/` | 本次实际使用的权重、预处理、融合、资源标定及必要元数据 |
| `源码/` | 运行开始时冻结的真实代码、清洗包与依赖说明 |
| `报告/运行结果.json` | 指标、模型来源、优化核验、耗时、限制与提交资格 |

时间统一输出为 `YYYY-MM-DD HH:MM:SS`。五个优化字段为
`opt_generator_use_blast_furnace_gas`、`opt_generator_use_coke_gas`、
`opt_generator_use_converter_gas`、`opt_generator_1`、`opt_generator_all`，
三气种字段为统一答复明确的必填项，两个负荷字段继续按赛题提供，三表放入同一ZIP。

覆盖校验逐点比较预期网格，拒绝缺行、多行、重复、乱序和时间错位。完整 half_test
的预测表为2016行，起报范围为2025-10-11 00:00至10-31 23:45；优化表使用相同
时间网格，共2016行、22个发布时刻（含首尾部分窗口）。quick仅对优化覆盖前两个完整自然日，
共192行、3个发布时刻。
每条优化指令的生成时刻早于生效时刻，运行摘要记录每日发布时刻及96步约束核验。

模型元数据与标定入口为 `模型/model_meta.json`，其他必要参数随实际模型分支保存。
新归档在模型元数据中保存重载所需选择参数、运行范围和源码指纹，重载不依赖
`报告/运行结果.json`。已有旧包可从其模型元数据恢复资源短头融合等必要设置。
ZIP只含有效结果CSV、源码与模型，不含原始数据、实验缓存、折外数组、日志或
`.gitignore`；仓库中的 `.gitignore` 正常保留。`报告/` 仅保留JSON和日志两个文件。
技术报告、答辩材料由用户编写，缺少手工资料不阻断机器结果生成。

`SUCCESS_INFER` 表示测试推理完成，是否可提交另看 `submission_check` 和
`submittable`。缺少必要优化资源或解未通过校验时记录 `BLOCKED_OPT` 或具体原因，
不伪造 `opt_result.csv`。当前实验及未经正式物理核验的模拟包均不能冒充可提交产物。

复用已有合法最终模型时可运行：

```powershell
python main.py infer --experiment --reuse-run tmp/tmp_outputs/<已有最终模型运行>
python main.py verify --run-dir tmp/tmp_outputs/<新运行>
```

`--reuse-run` 也可指向本项目结果包的本地解压目录，不要求解压到原项目路径；
模型路径兼容 Windows 与 Linux。ZIP 中的原始数据仍由赛事环境提供，不随包分发。

复用模型的训练截止须早于测试起报点；正式训练只使用已保存的晋级配方。
归档模型需通过保存重载一致性检查，改变数据、代码或配置后以新运行记录为准。
源码快照在训练前生成，保存模型及打包时只核验、不覆盖。运行中修改正式源码或
冻结快照会拒绝归档并记录失败，防止新代码与旧训练结果混装；历史运行快照不更新。
